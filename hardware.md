# **Google Colab AI Pro Runtime Hardware Specifications & Comparison**

# **Technical Reference & System Architecture Guide (Verified & Updated Edition)**

# **Section 1: Executive Overview**

The **Google AI Pro** subscription grants users allocated Compute Units (CUs) and direct access to high-performance hardware accelerators within the [Google Colaboratory](https://colab.research.google.com/signup) ecosystem. Subscribers on this configuration can provision the full spectrum of computational hardware, spanning cost-efficient standard CPUs, mainstream inference GPUs (T4, L4), high-throughput enterprise and workstation-server accelerators (**A100**, **Blackwell-based G4**, **H100**), and specialized Tensor Processing Units (TPU v5e-1, TPU v6e-1 Trillium).

# **Key Architectural & Provisioning Behaviors**

* **The High RAM Toggle:** Enabling or disabling the "High RAM" switch in Colab runtime settings does not merely scale memory limits within a virtual container. It triggers a physical or virtual re-allocation of host infrastructure:  
  * **System Host Memory & vCPUs:** Toggling High RAM scales physical CPU cores (vCPUs) and system RAM capacity by approximately 2x to 4x, preventing system bottlenecks during intensive data pre-processing, model weight loading, or ETL pipelines.  
  * **Dynamic GPU & Memory Bandwidth Swap (A100):** For the [NVIDIA A100](https://www.thundercompute.com/blog/nvidia-a100-specs-full-guide) platform, changing the memory toggle dynamically routes the execution environment to entirely separate hardware targets ([Colab GPUs Features & Pricing](http://mccormickml.com/2024/04/23/colab-gpus-features-and-pricing/)). **Standard RAM** provisions an **A100 SXM4 40 GB HBM2** model (**1,555 GB/s** memory bandwidth at \~5.40 CU/hr), whereas **High RAM** switches the session to an **A100 SXM4 80 GB HBM2e** model (**2,039 GB/s** memory bandwidth at \~7.52 CU/hr)—delivering 2x the VRAM capacity and a **31.1% increase in memory bandwidth**.  
* **Enterprise Hopper Access (NVIDIA H100):** While [NVIDIA H100](https://www.nvidia.com/en-us/data-center/h100/) availability in Colab can be subject to regional capacity queues or tier rollouts ([explainx.ai](https://explainx.ai/blog/google-ai-pro-colab-a100-h100-200-compute-units-claimed-vs-verified-2026)), it is available alongside the T4, L4, A100, and G4 GPUs in this Google AI Pro environment, providing **80.0 GB HBM3** memory and **3,350 GB/s (3.35 TB/s)** of memory bandwidth on SXM5 nodes ([Thunder Compute](https://www.thundercompute.com/blog/nvidia-h100-specs-full-guide)).

# **Section 4: Technical Deep-Dive & Architecture Insights**

* **A100 VRAM Doubling & Bandwidth Boost Mechanics:** Colab handles the A100 runtime allocation differently from other GPUs ([Chris McCormick](http://mccormickml.com/2024/04/23/colab-gpus-features-and-pricing/)). Requesting an A100 under *Standard RAM* attaches the instance to a physical **A100 40 GB SXM4** board backed by Google Cloud's `a2-highgpu-1g` shape (12 vCPUs, 85 GB host RAM / \~83.5 GiB usable, **1,555 GB/s HBM2**, \~5.40 CU/hr) ([Vantage](https://instances.vantage.sh/gcp/a2-highgpu-1g)). Enabling *High RAM* re-routes the session allocation to an **A100 80 GB SXM4** board backed by `a2-ultragpu-1g` (\~167.1 GiB usable host RAM, 12–24 vCPUs, **2,039 GB/s HBM2e**, \~7.52 CU/hr) ([Spare Cores](https://sparecores.com/server/gcp/a2-ultragpu-1g)). Beyond doubling VRAM and host RAM, upgrading from HBM2 to HBM2e increases memory bandwidth by **31.1% (from 1,555 GB/s to 2,039 GB/s)**, directly accelerating memory-bandwidth-bound autoregressive LLM decoding. (Form Factor Note: Both the 40 GB PCIe and 40 GB SXM4 variants share identical memory bandwidth [1,555 GB/s HBM2] and dense compute [312 TFLOPS BF16], but SXM4 is the accurate physical form factor provisioned on GCP/Colab.)  
* **Blackwell G4 Cost, Compute & Memory Bandwidth Trade-Offs:** The G4 instance ([NVIDIA RTX PRO 6000 Blackwell Server Edition](https://www.nvidia.com/en-us/data-center/rtx-pro-6000-blackwell-server-edition/), built on the **GB202** die and Google Cloud's `g4-standard-48` AMD EPYC Turin platform with 48 vCPUs and 180 GB host RAM / \~176.9 GB usable) represents a major leap in VRAM capacity and low-precision compute density ([Barrack AI](https://blog.barrack.ai/google-cloud-fractional-g4-vgpu-security/)). Packing **95.6 GB of usable GDDR7 memory (96 GB physical)** at **1,597 GB/s (\~1.6 TB/s)** of memory bandwidth ([Lenovo Press](https://lenovopress.lenovo.com/lp2263-thinksystem-nvidia-rtx-pro-6000-blackwell-server-edition-pcie-gen5-gpu)), the G4 delivers **\~480–500 TFLOPS of dense FP16/BF16 compute** and **\~960–1,000 TFLOPS (1 PFLOPS) with 2:4 structured sparsity**, plus native **FP8 (\~1 PFLOPS dense / 2 PFLOPS sparse)** and **FP4 (\~2 PFLOPS dense / 4 PFLOPS sparse)** Tensor Core execution ([StorageReview](https://www.storagereview.com/review/nvidia-rtx-pro-4500-blackwell-server-edition-review)). Compared to the A100 80 GB (\~7.52 CU/hr vs. \~8.71 CU/hr on G4), the G4 provides **19.5% more VRAM** and **\~1.6x higher dense BF16 compute** (or **\>3x higher compute when utilizing FP8/FP4**), though the A100 80 GB retains a **27.7% memory bandwidth advantage (2,039 GB/s HBM2e vs. 1,597 GB/s GDDR7)** for pure bandwidth-bound BF16 token generation.  
* **Mainstream GDDR6 Bandwidth Parity (T4 vs. L4):** Both the [NVIDIA T4](https://flopper.io/gpu/nvidia-t4-16gb) (16 GB physical / 15.0 GB usable GDDR6 on a 256-bit bus at **300–320 GB/s**) and the [NVIDIA L4](https://www.cloudpe.com/blog/nvidia-l4-gpu-specs/) (24 GB physical / 22.5 GB usable GDDR6 on a 192-bit bus at **300 GB/s**) share roughly identical external memory bandwidth. However, the L4 (`AD104` die) compensates for its narrower 192-bit memory bus with a **12x larger L2 cache (48 MB vs. 4 MB on T4)**, **nearly 2x dense FP16 compute (121 TFLOPS dense / 242 TFLOPS sparse vs. 65 TFLOPS)**, native **bfloat16** and **FP8** support, and 50% more usable VRAM.  
* **TPU vs. GPU Framework & Generational Scaling:**  
  * **Software Stack Constraints:** While GPUs rely on NVIDIA's CUDA drivers for out-of-the-box compatibility with PyTorch and standard LLM ecosystem tools, Cloud TPUs rely on XLA (Accelerated Linear Algebra) compilation and are optimized primarily for **JAX**, **TensorFlow**, and **PyTorch/XLA**.  
  * **Generational Leap (v5e to v6e):** The transition from [Cloud TPU v5e (ViperLite)](https://docs.cloud.google.com/tpu/docs/v5e) to [Cloud TPU v6e (Trillium)](https://docs.cloud.google.com/tpu/docs/v6e) delivers a **4.66x (\~4.7x) compute performance increase** (from 197 TFLOPS to 918 TFLOPS in BF16), doubles total HBM capacity from **16 GB to 32 GB**, and **doubles HBM memory bandwidth from 819 GB/s (800 GiB/s) to 1,638 GB/s (1,600 GiB/s)**. Notably, a single TPU v6e-1 chip offers slightly higher memory bandwidth (1,638 GB/s) than both the A100 40 GB (1,555 GB/s) and the Blackwell G4 GPU (1,597 GB/s) at a fraction of the Compute Unit burn rate (\~2.50 – 3.80 CU/hr).  
* **Hopper H100 Architecture & Tier Availability:** The [NVIDIA H100 SXM5](https://www.thundercompute.com/blog/nvidia-h100-specs-full-guide) accelerator (backed by Google Cloud's `a3-highgpu-1g` platform with up to 26 vCPUs and 234 GB host RAM) pairs **80.0 GB of HBM3 memory** at **3,350 GB/s (3.35 TB/s)** with **989.5 (\~990) TFLOPS dense (1,979 TFLOPS sparse) FP16/BF16** and **1,979 TFLOPS dense (3,958 TFLOPS sparse) FP8** via its Hopper Transformer Engine. (By contrast, PCIe H100 variants use HBM2e at **2,000 GB/s** and deliver **756.5 TFLOPS dense / 1,513 TFLOPS sparse FP16/BF16**.) While H100 access is subject to dynamic capacity queues and tier rules across Google AI plans ([explainx.ai](https://explainx.ai/blog/google-ai-pro-colab-a100-h100-200-compute-units-claimed-vs-verified-2026)), when provisioned it offers the highest memory bandwidth (3.35 TB/s—more than 2x the G4 and 64% higher than the A100 80 GB) at the highest burn rate (\~14.0 – 18.6 CU/hr, or \~\$1.86/hr) ([Reddit](https://www.reddit.com/r/comfyui/comments/1rg3hra/google_colab_finally_adds_modern_gpus_rtx_6000/)).

# **Section 5: Specification Verification & Audit Summary**

* **Confirmed Accurate Specifications:**  
  * **Usable ECC VRAM & HBM Capacities:** All accelerator memory capacities reported by `nvidia-smi` and TPU tools in Colab—**15.0 GB** on T4 (16 GB physical), **22.5 GB** on L4 (24 GB physical), **40.0 GB / 80.0 GB** on A100, **95.6 GB** on G4 (96 GB physical), **80.0 GB** on H100, **16.0 GB** on TPU v5e-1, and **32.0 GB** on TPU v6e-1—are verified as accurate ([Chris McCormick](http://mccormickml.com/2024/04/23/colab-gpus-features-and-pricing/), [Google Cloud](https://docs.cloud.google.com/compute/docs/gpus)).  
  * **Dense Compute Figures for T4, L4, A100, H100, and TPUs:** Peak dense throughput ratings for T4 (**65 TFLOPS FP16**), L4 (**121 TFLOPS dense FP16/BF16**), A100 (**312 TFLOPS dense FP16/BF16**), H100 SXM5 (**990 TFLOPS dense FP16/BF16**, **1,979 TFLOPS dense FP8**), TPU v5e-1 (**197 TFLOPS BF16**, **393 TOPS INT8**), and TPU v6e-1 (**918 TFLOPS BF16**, **1,836 TOPS INT8**) match official hardware datasheets.  
* **Key Corrections & Refinements Applied in This Edition:**  
  * **Added Memory Bandwidth Across All Hardware:** Integrated official memory bandwidth specifications across all tables and sections: **300–320 GB/s** (T4), **300 GB/s** (L4), **1,555 GB/s** (A100 40 GB HBM2), **2,039 GB/s** (A100 80 GB HBM2e SXM4), **1,597 GB/s** (G4 RTX PRO 6000 Blackwell Server Edition GDDR7), **3,350 GB/s** (H100 SXM5 HBM3), **819 GB/s** (TPU v5e-1), and **1,638 GB/s** (TPU v6e-1).  
  * **G4 (RTX PRO 6000 Blackwell Server Edition) Dense vs. Sparse TFLOPS Normalization:** The original document listed **\~960 TFLOPS BF16** for the G4 alongside *dense* TFLOPS for the L4 (121 TFLOPS), A100 (312 TFLOPS), and H100 (990 TFLOPS), and claimed the G4 had "over 3x the raw compute performance of the A100 80 GB" in BF16. Official [NVIDIA](https://www.nvidia.com/en-us/data-center/rtx-pro-6000-blackwell-server-edition/) and [StorageReview](https://www.storagereview.com/review/nvidia-rtx-pro-4500-blackwell-server-edition-review) specifications confirm that **\~960–1,000 TFLOPS (1 PFLOPS)** on the RTX PRO 6000 Blackwell is the **2:4 structured sparsity** rating; its **dense** FP16/BF16 Tensor throughput is **\~480–500 TFLOPS** (\~1.6x the A100's 312 TFLOPS dense, or \~1.6x the A100's 624 TFLOPS sparse). The G4 achieves \>3x the A100's BF16 compute when leveraging its native **FP8 (\~1,000 TFLOPS dense / 2 PFLOPS sparse)** or **FP4 (\~2,000 TFLOPS dense / 4 PFLOPS sparse)** Tensor Cores.  
  * **NVIDIA L4 Die Designation:** Corrected the L4 architecture label from `AD102/104` to **AD104** ([CloudPe](https://www.cloudpe.com/blog/nvidia-l4-gpu-specs/)). The larger `AD102` die powers the NVIDIA L40 and L40S, whereas the 72W L4 uses the `AD104` die.  
  * **Separated A100 Standard vs. High RAM Burn Rates & vCPU Specs:** Separated the A100 Compute Unit burn rate in Tables 3.1 and 3.2 into **\~5.40 CU/hr** for Standard RAM (40 GB) and **\~7.52 CU/hr** for High RAM (80 GB) ([Chris McCormick](http://mccormickml.com/2024/04/23/colab-gpus-features-and-pricing/)), and noted that Google Cloud's underlying `a2-ultragpu-1g` instance natively allocates 12 vCPUs (scaling up to 12–24 vCPUs depending on container mapping) ([Vantage](https://instances.vantage.sh/gcp/a2-highgpu-1g)).  
  * **Included H100 Across All Tables:** Updated H100 availability to reflect user access and added H100 rows to both Table 3.1 (Standard RAM) and Table 3.2 (High RAM), distinguishing between SXM5 (**3,350 GB/s HBM3**, **990 TFLOPS dense BF16**) and PCIe (**2,000 GB/s HBM2e**, **756.5 TFLOPS dense BF16**) specifications ([Thunder Compute](https://www.thundercompute.com/blog/nvidia-h100-specs-full-guide)).
  * **A100 40 GB Form Factor Verification (SXM4 vs. PCIe):** Verified that Colab's Standard RAM A100 provisions an A100 40 GB SXM4 board (GCP `a2-highgpu-1g`), resolving occasional confusion with PCIe variants. Because both 40 GB PCIe and 40 GB SXM4 share identical memory bandwidth (1,555 GB/s HBM2) and Tensor Core throughput (312 TFLOPS dense FP16/BF16), kernel and precision arithmetic are identical, but SXM4 is the verified physical hardware designation for Colab.
