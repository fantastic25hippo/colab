# **Qwen 3.8 27B (Abliterated) & Google Colab GPU Execution Blueprint**

# **1\. Executive Summary & Architecture Overview**

This blueprint documents the end-to-end plan for running an uncensored/abliterated 27-billion-parameter coding worker model on Google Colab GPUs using a 200 Compute Unit (CU) monthly allocation from a [Google AI Pro subscription](https://note.com/kiyo_ai_note/n/n51c2053a8be7?hl=en), orchestrated locally by **Gemini** (via [Antigravity CLI](https://antigravity.google/docs/cli/overview/)) or **Grok**.

* **Model Clarification (`Qwen 3.8 27B` vs. `Falcon`):** The 27B "obliterated" model is [**Qwen 3.8 27B**](https://huggingface.co/Qwen/Qwen3.8-27B)—specifically [**OBLITERATUS/Qwen3.8-27B-OBLITERATED**](https://huggingface.co/OBLITERATUS/Qwen3.8-27B-OBLITERATED) and its derivatives—rather than Falcon. TII's [Falcon 3 series](https://huggingface.co/blog/falcon3) tops out at [10B parameters](https://huggingface.co/tiiuae/Falcon3-10B-Base) (with an abliterated proof-of-concept at [huihui\_ai/falcon3-abliterated:10b-instruct](https://ollama.com/huihui_ai/falcon3-abliterated:10b-instruct)), and the hybrid [Falcon-H1 series](https://huggingface.co/blog/tiiuae/falcon-h1) scales from 0.5B to 34B with no 3.8 or 27B release. "Obliterated" refers to **abliteration** ([Locally Uncensored Guide](https://locallyuncensored.com/blog/abliterated-models-guide.html))—orthogonal projection of refusal directions out of the model's weight matrices using toolkits like [OBLITERATUS](https://huggingface.co/spaces/Ngixdev/obliteratus).  
* **Orchestrator → Worker Split:**  
  * **Orchestrator (Local PC — 0 CU):** [Antigravity CLI](https://antigravity.google/blog/introducing-google-antigravity-cli) or Grok runs locally on the PC to handle high-level planning, architecture, and prompt preparation before any Colab GPU is connected.  
  * **Cloud Storage Backbone (Google Drive — 0 CU):** The quantized `.gguf` model weights (16.8 GB `Q4_K_M` or 19.5 GB `Q5_K_M`) and pre-built `llama-server` binary live in Google Drive rather than on the local PC. Because a remote Colab GPU cannot read files directly off a local PC's SSD ([Colab VS Code Issue \#210](https://github.com/googlecolab/colab-vscode/issues/210)), storing weights on a local PC would force a 22–45 minute upload over home internet on every boot. Mounting Google Drive via `colab drivemount` ([Colab CLI Reference](https://ai-tldr.dev/tools/google-colab-cli/)) transfers weights across Google's internal data-center backbone at 500 MB/s–2+ GB/s in **30 to 60 seconds**.  
  * **Worker Node (Remote Colab GPU via `colab-cli`):** Provisioned on demand via the [Google Colab CLI](https://developers.googleblog.com/introducing-the-google-colab-cli/) ([GitHub repo](https://github.com/googlecolab/google-colab-cli)). The worker executes the coding batch with thinking disabled (`enable_thinking=False`) and immediately shuts down (`colab stop` or [`runtime.unassign()`](https://stackoverflow.com/questions/74148849/how-to-terminate-colab-session-programmatically)) to eliminate idle compute unit drain.

## **Key Hardware Takeaway: L4 vs. A100 40GB**

* **When to pick the A100 40GB (`colab new --gpu A100`):** Because the A100 40GB delivers **5.2x the memory bandwidth** of the L4 for only **3.1x the hourly compute unit cost**, running a non-stop, pre-queued coding batch on an A100 40GB finishes in \~1/5th the time and burns **\~30% fewer compute units per 1,000 tokens** (0.0149–0.0213 CU vs. 0.0190–0.0317 CU on the L4), while also fitting the higher-precision **29 GB `Q8_0`** or **30 GB `FP8`** weights.  
* **When to pick the L4 (`colab new --gpu L4`):** Whenever you want to keep the model connected for a **multi-hour interactive workday** (such as a 4-hour block where the GPU pauses between prompts while you inspect code or run tests), the L4 is far safer because idle minutes only cost **\~1.71 CU/hour** instead of **5.37–8.71 CU/hour**.

# **5\. Colab Billing Mechanics & 20-Workday Runtime Schedule**

Google Colab bills compute units for **every minute the GPU runtime VM is connected**, including package installation, weight loading, and idle pauses ([GitHub Issue \#4868](https://github.com/googlecolab/colabtools/issues/4868), [r/GoogleColab FAQ](https://www.reddit.com/r/GoogleColab/comments/11aimj6/are_google_colab_compute_units_consumed_even_when/), [Medium Colab Breakdown](https://medium.com/@jprachir/reality-check-if-you-are-opting-for-google-colaboratory-colab-2c9d36d3c0bd)). # **6\. Future Reference: Specific GPU & Inference Optimization Tweaks**

When you are ready to tune the GPU setup beyond baseline defaults to maximize tokens per second and further reduce compute unit burn, revisit these five specific tweaks:

1. **Enable Speculative Decoding (`MTP` or `DFlash2` Sidecar — 1.6x to 2.4x Single-Stream Speedup):**  
   * **How it works:** A small draft head predicts 3–4 tokens ahead and the 27B model verifies them in one pass. Because code syntax and indentation are highly predictable, draft acceptance hits **53–67%** ([Blackfrost Benchmarks](https://huggingface.co/Blackfrost-AI/Qwen3.8-27B-ABLITERATED-GGUF)).  
   * **Single-file `MTP` command (`llama.cpp`):** Pass `--spec-type draft-mtp --spec-draft-n-max 3` when serving [**Blackfrost-AI/Qwen3.8-27B-ABLITERATED-GGUF**](https://huggingface.co/Blackfrost-AI/Qwen3.8-27B-ABLITERATED-GGUF) (the 65th-block MTP head is already embedded inside the main `.gguf`).  
   * **Two-file `DFlash2` command (Maximum Speed on A100/G4):** Pair the main `Q4_K_M` file with `dflash-Qwen3.8-27B-ABLITERATED-BF16.gguf` (3.86 GB) using `--spec-type draft-dflash --spec-draft-n-max 3 --spec-draft-n-min 0 --spec-draft-p-min 0 -ngl all -ngld all`, which reached **109.31 tok/s median** (up to 118.60 tok/s) on the Colab G4 Blackwell GPU.  
2. **Use Parallel Subtask Batching (3x to 5x Aggregate Throughput Multiplier):**  
   * **How it works:** Reading 16.8 GB of weights from VRAM for a single token leaves the GPU's Tensor Cores mostly waiting on memory. Sending **4 independent coding prompts at once** lets the GPU read the 16.8 GB weights **once** and compute tokens for all 4 files simultaneously.  
   * **Setup:** Launch `llama-server` with `-np 4` (4 parallel slots) or run `SGLang` / `vLLM`, and have [Antigravity CLI](https://antigravity.google/docs/cli/overview/) dispatch 4 independent module/file tasks concurrently. On an A100 or G4, combined throughput jumps to **250–350+ tokens/second**, cutting batch runtime by 60–75%.  
3. **Switch to Hardware-Native Tensor Core Kernels (`Marlin AWQ`, `FP8`, or Blackwell `NVFP4` — 25–40% Speedup):**  
   * **How it works:** Standard `GGUF` unpacks quantized weights on the fly. Using hardware-native Tensor Core formats avoids unpacking overhead: the L4 and G4 have native **FP8** Tensor Cores, and the G4 Blackwell has native **4-bit (`NVFP4` / `W4A4`)** Tensor Cores ([Google AI Pro GPU Guide](https://note.com/kiyo_ai_note/n/n51c2053a8be7?hl=en), [Blackfrost Card](https://huggingface.co/Blackfrost-AI/Qwen3.8-27B-ABLITERATED-GGUF)).  
   * **Setup:** On `SGLang` or `vLLM`, load [**medismera/Qwen3.8-27B-OBLITERATED-Mythos-Class-Agentic**](https://huggingface.co/medismera/Qwen3.8-27B-OBLITERATED-Mythos-Class-Agentic) using `--revision awq` (Marlin 4-bit kernel for 24 GB L4) or `--revision fp8` (native 8-bit Tensor Core execution for 40 GB+ A100/G4).  
4. **Turn On FlashAttention \+ Quantized KV Context Cache (Eliminates Long-Context Slowdowns):**  
   * **How it works:** On large coding prompts (16K–128K tokens), reading the uncompressed 16-bit KV cache becomes a major memory-bandwidth bottleneck. Compressing the KV cache to 8-bit or 4-bit keeps generation speed fast as context grows and saves several gigabytes of VRAM.  
   * **Setup:** In `llama.cpp`, pass `-fa on -ctk q8_0 -ctv q8_0` ([Blackfrost Guide](https://huggingface.co/Blackfrost-AI/Qwen3.8-27B-ABLITERATED-GGUF)) or `-ctk q4_0 -ctv q4_0` ([jenerallee78 Guide](https://huggingface.co/jenerallee78/Qwen3.8-27B-Abliterated-SFT)). In `SGLang`, pass `--kv-cache-dtype fp8_e5m2` ([medismera Guide](https://huggingface.co/medismera/Qwen3.8-27B-OBLITERATED-Mythos-Class-Agentic)).  
5. **Lock In Optimal Sampling & Prompt Hygiene (Zero Refusals \+ No Infinite Loops):**  
   * **Settings ([OBLITERATUS V3 Card](https://huggingface.co/OBLITERATUS/Qwen3.8-27B-OBLITERATED)):** Always pass `repetition_penalty=1.15` (prevents deterministic import/boilerplate loops), `enable_thinking=False` (skips chain-of-thought overhead since Gemini/Grok already did the planning), `temperature=0` for single-shot code generation (or `0.1–0.3` for multi-turn agent loops), and an **empty/minimal system prompt** (since heavy system-prompt boilerplate can re-trigger latent refusal directions, per [jenerallee78 bisection tests](https://huggingface.co/jenerallee78/Qwen3.8-27B-Abliterated-SFT)).
